## 設計原則

1. **原価がかかる場所（ストレージ・AI）で課金し、テキスト＋小さいファイルは無料**
2. **石（消費型通貨）でストレージと AI の両方をまかなう** — 原価の性質（ストレージ=持続コスト、AI=都度コスト）の違いを、消費の仕方で吸収する（→ ケルン消費モデル）
3. **能動権は本人、受動恩恵はワークスペース全体に帰属させる** — オリジナルのアップロードと AI への能動的な依頼は支援者本人のみ。閲覧・ダウンロード・Heartbeat による AI の自発的な指摘は、ケルンに石があれば全メンバーが受けられる。これにより「管理者が課金を渋ると誰も使えない」デッドロックを避けつつ、1人の支援が部全体を照らす
4. **チャット履歴は無料プランでも無制限** — テキストの原価はほぼゼロ。履歴制限による課金誘導はしない
5. **ゲスト招待は全プラン無料・無制限** — 社外コラボレーションの普及導線なので課金設計で制限しない
6. **OSS版に機能ペイウォールを作らない** — Cloud で課金するのは「ホストされた資源（容量・AI・バックアップ）と運用の手間」であって機能ではない

## プラン構成

| | **Free** | **Solo** | **Team**（将来） | **Expedition** |
|---|---|---|---|---|

買い増し（トップアップ）: アクティブな Solo / Team の購読者は、単発で石パックを購入してケルンに追加できる（AI を使いすぎた月の調整用）。石に有効期限はない。

## 採用の入口と複雑さの段階開示

採用の最初の一歩は、単純なメッセージで十分:

> **無料で、メンバー無制限・チャット履歴は永久・大きすぎなければファイルもアップロード可・画像は圧縮されるがそのままアップロードできる。**

- 入口では石・ケルン・風化・買い増しといった仕組みを**一切見せない**。これらは「もっと容量や AI が要るとき」に初めて現れる
- **複雑さはアップグレード時にのみ開示する**。入口が単純なら、ケルン消費モデルの豊かさが採用の障壁にならない。まず使い始めてもらい、限界に触れたところで初めて石の話をする

## ギャラリーと無料層

ギャラリーの差別化価値（写真が案件に紐づき、地図に載り、報告書になる）は、**圧縮画像 + GPS + 撮影日時** で完全に成立する。GPS・日時は EXIF から抽出したテキストデータで原価ほぼゼロ、表示・地図ピン・報告書 PDF は長辺2048px の圧縮で足りる。

- → **ギャラリーの差別化は丸ごと無料層で動く**。写真を多用する現場（撮影が多い業種）でも、摩擦ゼロで価値を体験できる
- オリジナル（フル解像度）は「綺麗なまま見たい・保存したい」という別の、狭い需要への上位機能。差別化の本体ではない
- アップセルのレバーは2本に分かれる:
  1. **オリジナル画質** — 原画で保存・閲覧したい需要
  2. **保有容量** — 圧縮でも枚数が多ければ 10GB を超える（圧縮 500KB/枚で約2万枚）
- 高頻度の撮影ユーザーは①画質より先に②容量で課金に到達する。これはフェアで予算化しやすい導線

## ケルン消費モデル

本プランの核。石は「持っている間だけ権利が有効になる定額」ではなく、**ケルンに積まれ、使うほど減っていく消費型の通貨**として扱う。

### 石の供給と消費

- **供給**: Solo / Team の購読が毎月一定数の石をワークスペースのケルンに積む。トップアップで単発購入も可。石は失効しない（前払いなので、いつ使っても原価は使用時にしか発生せず、こちらに不利益がない）
- **消費（2種類）**:
  - **AI 能動利用** = 都度消費（1依頼ごとに石が減る）。AI は使った瞬間にコストが終わる「フロー型」なので、ゆっくり消費しても元が取れる
  - **ストレージ保有** = 家賃として毎月消費（保有 GB に応じてケルンが少しずつ削れる）。ストレージは存在し続ける限りコストが発生する「ストック型」なので、アップロード1回で引き切るのではなく毎月引く。これにより「1ヶ月課金して大量保存 → 放置」でも収支が閉じる
- ハートビートの巡回（一次判定）は原価僅少のため消費しない。発言時に生じるコストはケルンから支払う（→ 受動恩恵の原資）

### 風化（ケルンが 0 になったとき）

諸行無常 — ケルンは崩れる。消費で石が尽きると **Free 相当に戻る**。

- 新規のオリジナル/動画アップロードは停止
- 既存のオリジナルはロックされるが、**画像は圧縮版を配信して閲覧は継続**（思い出は見える）。動画・文書は「現在開けません」のプレースホルダ + 再課金導線
- **消えないもの**: 圧縮版の写真（実質無料で永久保存）と、貢献の記録（誰がいつ石を積んだか）。風化するのは「潤沢に支えられた状態」であって、思い出とコミュニティの記録ではない
- オリジナルは長期放置でコールドストレージへ退避し、保存コストの尻尾を有界化する

### ケルンの UI と世界観

- ワークスペースの設定に**ケルン画面**を置く。積まれた石＝残高、風化＝消費が視覚化される（数字が減るより枯渇不安が少ない）
- **貢献の記録は残る**: ビジュアルのケルンは風化するが、「◯◯先輩が積んだ石」は礎石・貢献タイムラインとして永続する（OB積み石の文化）
- **石を積むミニゲーム**（石の形を選ぶ・バランスよく積む）は、課金を「苦痛」から「創作」に変える喜びのレイヤー。ただし Phase 1 の課金ローンチを止めない後載せ機能とする（詳細は [`billing-minigame-design.md`](./billing-minigame-design.md)）
- 「地震」「人が蹴る」等のランダム演出は**見た目のみ**。前払い済みの石（買った価値）をランダムに壊さない（消えるのはユーザーが実際に使った分だけ）

## 提示の二面化（単一エンジン・二つの見せ方）

課金エンジンは石（消費）の単一だが、**提示はセグメントで二面化する**:

| セグメント | プラン | 見せ方 |
|---|---|---|
| 個人・コミュニティ（学生団体など） | Free / Solo | ケルンの世界観・風化・石積み（遊びと感情）。「石を積む」文言 |
| 法人・チーム | Team / Expedition | 退屈な定額として見せる。中身は同じ石でも Team の付与を潤沢にして風化を体感させない（「月額で全員が使える」） |

- 全セグメントに同じケルン UX を押し付けない。ライト層には魅力、実務層には単純さ
- 実装上は単一の課金エンジン（石・台帳・家賃）の上に、提示層（UI コピー・ダッシュボード）を2系統用意する

## 命名の意図

| 名前 | 役割 | 意図 |
|---|---|---|
| **Free / Solo / Team / Expedition** | プラン | ライト層が触れる Free は固有名を付けず分かりやすく。個人の登山（Solo）→ パーティ（Team）→ 遠征隊（Expedition）と規模の物語が通る |
| **石（Stone）** | 消費通貨・課金行為 | ケルンは通る人が石を積んで道標になる。課金ボタンは「石を積む」。あとの人のために積む文化が支払いに意味を与える |
| **ケルン（Cairn）** | 残高・世界観 | プロダクト名そのもの。積まれ、風化し、貢献が礎石として残る |

不採用・回避した候補と理由（再検討の無駄を省くため記録）: Trail（無料プランに固有名は不要）、Alpine（Alpine Linux / Alpine.js を連想）、Trailhead（Salesforce の学習サービス名）、Climb（汎用的すぎる）、Belay（登山者以外に通じない）、Sherpa（民族名の商用流用は批判の前例があり使用しない）、歩荷（国際展開で通じない）。**プラン名・通貨名はマーケティング上の名称であり、DB・コードの識別子には入れない**（ブランド改名に耐えるため。詳細は実装設計書）

## セルフホスト版との関係

**セルフホストは Expedition 相当の機能を自前のインフラで利用できる。** 機能制限・ペイウォールは設けない（設計原則 6）。

- ストレージは自前、AI は BYOK（自分の API キー）で無条件利用可。石・ケルン・風化の機構そのものが無効化される
- SSO / 監査ログ等の法人向け機能も、実装され次第 OSS に含める
- サポートはコミュニティベース。商用サポート・FDE 導入支援が必要な場合は別契約（Expedition と同じ窓口）

## ロールアウト順序

- **初期は Free + Solo のみ**で開始する
- Team は団体・法人の引き合いが出てから追加。価値は「全員がオリジナルをアップロードでき、石が潤沢」であり、石のまとめ買いではない。アクティブな Solo が増えて月額合計が Team 価格に近づいた WS には切り替えを提案する
- Expedition の収益の本体はプラン料金ではなく **FDE 導入支援と年間サポート契約**。クラウドかセルフホスト支援かの判断も FDE が伴走して行う

## 決済の実務

- **購入導線は当面 Web のみ**（Stripe 想定）。アプリ内課金（IAP）は実装コストと手数料のため初期は見送り
- アプリ内では Web 決済ページへのリンクアウトで誘導する。日本ではスマホソフトウェア競争促進法（2025年末全面施行）により、リンクアウト誘導が規約リスクなしで成立しやすい
- 将来 IAP を導入する場合、アプリ経由価格は **¥450**（手数料 30% 控除後の手取り約 ¥315 ≒ Web の ¥300。二重価格の定石）
- 年払い（¥3,000/年 など）やトップアップのまとめ買いで決済手数料率を改善する

## 原価モデル（無料枠・サイズ閾値・家賃レートの根拠）

前提（2026-06 時点の想定。変動したらここを更新する）: Supabase Storage **$0.021/GB/月**、超過 egress **$0.09/GB**、為替 ¥150/$、Stripe 手数料 3.6%。

| 指標 | 値 |
|---|---|
| 保存原価 | 約 **¥3.2/GB/月** |
| Solo の純収入 | ¥300 × 0.964 ≒ **¥289/月** |
| 粗利ゼロの損益分岐 | **約90GB-月**ぶんの保存 |
| Free 10GB が満杯の場合の原価 | ¥32/月/WS |
| 圧縮画像1枚（〜500KB） | ¥0.002/月 |
| 文書 5MB 1ファイル | ¥0.016/月 |
| egress（配信） | **¥13.5/GB** |

導かれる結論:

- **赤字ラインは「1ファイル何MB」ではなく「WS 合計何GB を何ヶ月保つか」で決まる**。だからストレージは家賃（保有 GB-月）で課金する。アップロード1回引きにすると、使い切った後も居座るファイルの保存コストで赤字になる
- **家賃レート（石/GB/月）は実保存原価（¥3.2/GB/月）以上に設定する**。これを守れば、前払いした石をいつ消費しても必ず元が取れる
- 圧縮画像は実質無料で配布できる（3,000枚でも月¥5）ため、LINE 方式（無料=圧縮版、オリジナル=有料）は原価面で安全に成立する
- **本当の赤字リスクは保存ではなく egress**。だから風化時もオリジナルは配信せず圧縮版を返し、オリジナル一括ダウンロードは頻度の低い操作として設計する

## 未決事項

- 石の単価・月次付与数・家賃レート・AI 1依頼あたりの消費数（原価シミュレーションで確定）
- AI の天井を「減る残高」で見せるか「毎月リセットの上限」で見せるか（後者の方が枯渇不安が少ない。山岳部向けには後者を推奨）
- 画像圧縮の最終パラメータ（長辺 px・品質）と文書 5MB 上限の妥当性（Phase 0 の計測で検証）
- 風化後のオリジナルのコールド退避までの猶予期間、最終削除の是非
- Team の確定価格と、Solo との併存（Team 加入時の既存 Solo の扱い）
- BYOK の開放範囲（思想優先で全開放 or 収益優先で Team 以上）
- 消費税の扱い（Stripe Tax 導入の要否）
