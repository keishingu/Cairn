# 石積みミニゲーム設計（課金体験）

> **ステータス**: 現行の設計合意（作成: 2026-07-20、実装未着手。課金ロードマップ Phase 3 の後載せ機能）
> [`billing-implementation-design.md`](./billing-implementation-design.md) §10 のケルン画面に載せる「石を積むミニゲーム」の構想。課金エンジン本体（台帳・家賃・風化）は同書、プラン設計は [`pricing-plan-design.md`](./pricing-plan-design.md) を参照。

---

## 1. コンセプト

山では、山頂や峠などにケルン（Cairn）を積む文化がある。課金を「決済」ではなく**みんなでケルンを積み上げる体験**として表現する。サービス維持のためのお金ではなく「この山を一緒に育てている」という感覚を作ることが目的。

普通の SaaS は「料金を支払いました」で終わるが、Cairn では「あなたもこの山に石を一つ積みました」という物語になる。課金がプロダクトとコミュニティへの参加を象徴する体験になり、プロダクト名を最も自然に活かせる演出となる。

## 2. 位置づけ: 積む先は「貢献レイヤー」（永続）

課金エンジンには2つのレイヤーがある（実装設計書 §10「貢献の記録」）:

| レイヤー | 実体 | 増減 |
|---|---|---|
| **残高**（クレジット） | `SUM(credit_ledger.delta)` | 家賃・AI 消費で減る。0 以下で風化 |
| **貢献の記録**（礎石・タイムライン） | `subscriptions` + `credit_ledger` の付与行から導出 | **永続。減らない** |

**ミニゲームで積む石は貢献レイヤーに属する**。一度積んだ石は家賃や AI 消費で消えることはない。「先月置いた私の石が溶けて消えた」という体験を絶対に作らないための決定であり、演出（地震・蹴り等）でも購入済みの価値を壊さないという実装設計書の原則と同根。

残高の増減は石の増減ではなく、ケルン全体の色で表現する（§6）。

## 3. 石の単位: 決済イベント → 積み石の変換

ゲームの石はクレジット（課金エンジンの「石」）とは**別の単位**。1決済イベントを数個の積み石に変換する。

- 基準: **¥300（Solo 1口）= 積み石1個**。大口トップアップ（例: ¥3,000）= 10個
- 大量の石を1個ずつ置くのは面倒なので、以下のいずれか（併用可）で解決する:
  - **ワンクリックまとめ置き**（10個が連続で「コトコトコトッ」と積み上がる）
  - **大きい石・特殊形状の石**（❤️ / ⭐️ 等）に変換して個数を圧縮する
- クラブのケルン表示は**積んだ石の数**で表現し、累計課金額は出さない（お金臭さを消す）
- UI 文言上、クレジットの「石」とゲームの「積み石」を同じ語で呼ぶと混乱するため、文言設計時に呼び分けを決める（未決 → §12）。コード識別子にブランド名を入れない原則は本機能にも適用する

## 4. 基本フロー

### 目の前で決済したとき（初回購読・トップアップ）

```
課金（Stripe Checkout 外部遷移）
 ↓
決済成功 → success_url でケルン画面に帰着
 ↓
積み石を受け取る
 ↓
好きな場所へドラッグして積む（または「置く」ボタン）
 ↓
「コトッ」
 ↓
ケルンが保存される
```

決済完了画面がそのままゲームになる。**30秒くらい遊べて閉じる**のがちょうどいい長さ。

注意: success_url 帰着時点では Stripe Webhook が未処理の可能性がある。ゲーム側は楽観的に積み石を渡して開始し、台帳付与は Webhook 側で確定させる（表示と台帳の整合は付与 reason + ref_id で突合）。

### 画面の前にいないとき（月次更新 = `invoice.paid`）

積み石の付与イベントの大半は月次更新で、そのときユーザーは不在。**持ち越しキュー**で解決する:

- 未積みの石はキューに溜まり、次にケルン画面を開いたときに「未積みの石が2個あります」と表示 → その場で積める
- 通知やバッジでの誘導は控えめに（課金導線を邪魔しない原則）。ケルン画面への再訪動機として自然に機能させる

## 5. 積み方式: スナップ方式を初期実装、物理は後載せ

**Phase 3 初期はスナップ方式（物理は見た目だけ・必ず置ける）を採用する**:

- ケルン側に「次に置ける場所」のアンカーポイント（スロット）を持たせる
- ドラッグするとアンカー付近で半透明ゴーストが吸い付き、離すと短いアニメーションで着地 → 少し揺れて「コトッ」（SE）
- 置き位置はスロット番号として保存。**失敗が存在せず、保存が軽く、全メンバーの画面で同一のケルンを決定論的に再現でき、モバイルブラウザでも軽い**
- 着地時の揺れ・風での微動など「物理っぽさ」は CSS / スプリングアニメーションで演出する

本物の 2D 物理エンジン（matter.js 等: 実際に転がり・傾き・積み重なる）は後載せの演出強化とする。導入する場合も、**転げ落ちた石は消えず手元トレイに戻って積み直せる**・**安定した石はその場で固定化し既存のケルンを崩さない**を守る（30秒の体験に失敗状態は要らない）。

## 6. 風化の表現: 色で示す

残高の状態（`resolveWorkspaceState`）はケルン全体のトーンで表現する:

- **funded**: 石は Cairn ハイライトカラー
- **weathered（風化）**: ケルン全体がグレーになる。再び石が積まれると色が戻る

**石1個ずつを個別に灰色化しない**。ゲームの石とクレジットは単位が別（§3）なので石単位のマッピングは成立せず、「どの石から風化するのか＝誰の石が死んだのか」という問いを生んでしまう。風化は WS の状態であり、ケルン（貢献の形）は崩れない — 色が抜けるだけ。

## 7. プラン別の扱い

| プラン | 扱い |
|---|---|
| Free | ケルンは閲覧のみ（積み石の供給源がない）。入口では石・ケルンの仕組み自体を見せない（段階開示の原則） |
| Solo | 本機能のメインターゲット。購読・トップアップで積み石を獲得 |
| Team | **石積み可能**。ただし WS 定額で支払うのは管理者1人のため、そのままだと積めるのも1人になり「みんなで積む」が崩れる。**月次更新時にアクティブメンバー全員へ積み石を1個ずつ配布する**案を基本とする（支払いは1本でも、積む行為は全員に分配 — Team こそ全員でケルンを積める）。「提示の二面化」は請求画面の見せ方の方針であり、ケルン画面の遊びは Team でも提供する（請求 UI は簡素のまま） |
| Expedition | billing の概念自体が異なる（年契約・請求書払い）ため対象外 |
| セルフホスト | 課金無効のためケルン画面ごと非表示（実装設計書 §10 と同じ） |

## 8. モバイル

- モバイルブラウザ / WebView でも同じミニゲームを提供する。スナップ方式（§5）なら性能懸念は小さい
- アプリ（Expo）内には課金 UI を出さない方針（IAP 回避）のため、決済直後の体験は外部ブラウザ側で起きる。アプリ利用者は持ち越しキュー（§4）により、アプリに戻ってから WebView のケルン画面で積んで回収できる
- 物理演出（後載せ）がモバイルで厳しい場合は、モバイルはスナップ方式のまま PC のみ物理を有効化してもよい

## 9. コレクションとコミュニティ

- プロフィールに「積んだ石: 123個」を表示。年ごとの履歴表示（GitHub の草のような形式）も候補
- ワークスペース（クラブ・団体）ごとのケルンをみんなで積み上げる。表示は積んだ石の数（§3）
- 貢献の記録は風化しても残る（OB 積み石の文化 — pricing 設計書「ケルンの UI と世界観」）

## 10. 演出（後載せ含む）

- 基本: 置いた瞬間「コトッ」+ 軽い SE + 少し揺れる。積み上がると山風の音。派手ではなく**静かな達成感**
- 季節イベント: 雪が積もる・紅葉・夜になる
- 遠征記念石: 特定の山の限定石（山名の選定は実装時に検討）
- 環境アニメーション: 風で草が揺れる・鳥が飛ぶ・蝶が来る
- AI 生成の風景（積んだ石の形・数を反映した「あなたのケルン」の風景画像): 画像生成の原価が課金演出そのものに乗るため、やるなら**低頻度のレア報酬**等に絞る。現行 AI スタック（OpenAI・テキスト中心）の範囲外でもあり、優先度は最も低い

## 11. データモデル素案

貢献の記録自体は `credit_ledger` の付与行から導出できる（実装設計書 §4）。ミニゲームで追加が必要なのは**配置情報**のみ:

```
（テーブル名は中立語で。例: workspace_stone_placements）
  id             PK
  workspace_id   → workspaces.id (cascade)
  placed_by      → profiles.id
  slot_index     int          ※ スナップ方式のスロット番号
  shape          enum/text    ※ 通常・大・特殊形状（❤️ / ⭐️ 等）
  ledger_ref     → credit_ledger.id（付与行との対応。未積みキューは「付与行に対応する placement がまだない状態」として導出）
  placed_at      timestamptz
```

- 未積みキューを専用テーブルにせず、付与行と placement の差分から導出する（台帳を正とする一貫性）
- 詳細（大口決済1回を何行の placement にするか等）は Phase 3 着手時に確定する

## 12. 実装上の注意・未決事項

**注意**:

- **課金導線を邪魔しない**。ゲームは決済完了後・ケルン画面内に閉じ、Checkout への遷移を遅らせる要素を入れない
- 演出（地震・蹴り等のランダムイベント）は見た目のみ。積んだ石・残高を壊さない

**未決**:

- クレジットの「石」とゲームの「積み石」の UI 文言上の呼び分け
- 大口決済の変換規則の確定（個数 vs 大石・特殊形状、レア石の排出率）
- Team の全員配布の詳細（1人1個で固定か、口数・人数比で変えるか）
- 未積みキューの上限・失効の要否（失効させない方向が原則に沿う）
- プロフィールの石数表示を跨ワークスペースで合算するか
