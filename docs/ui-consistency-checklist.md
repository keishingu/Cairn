# UI 一貫性 統一チェックリスト

画面ごとにバラついていた UI パターンを共通化し、挙動・見た目・文言を揃えるための作業リスト。
着手前にこのファイルでスコープと方針を確認し、対応したら該当項目にチェックを入れる。

> 方針の本文は [`frontend-guidelines.md`](./frontend-guidelines.md) を正とする。本ファイルは進捗管理用。

## 対応済み

- [x] **優先度1: 削除確認 UI の統一** — 共通 `ConfirmDialog` に抽出（`0277de4`）。あわせてリストの削除動線・「+」追加ボタンを共通パターンへ（`264d44b`）
- [x] **優先度2: 通知ベルの統一** — 位置・サイズがページごとに違ったため、各ページのヘッダー右上に統一（`48bac62`）
- [x] **優先度3: 保存方式の統一** — インライン編集=blur 自動保存 / フォーム=保存ボタン / ラベルを「保存・キャンセル」に統一（`34912ec`）
- [x] **前提: トースト基盤の導入** — 削除・保存の成功/失敗フィードバックを統一するための `@/lib/toast` + `<Toaster/>` を整備

- [x] **優先度4: 未読バッジの統一** — ヘッダーのドットと各所の数字バッジに分かれていたのを、共通 `UnreadBadge`（accent ピル・件数表示・99+ 丸め）に統一。ベルも件数表示に揃えた

## 未対応

- [ ] **優先度5: ボタンの統一** — 共通クラス（`btn` / `btn-primary` / `btn-ghost`）とインライン `style` 直書きの混在を解消。削除の赤ボタンが毎回手書きなので `btn-danger`（destructive）バリアントを定義して置き換える
- [ ] **優先度6: 空状態の統一** — 文言が「まだ〜がありません / まだ〜はありません / 〜がいません」で揺れ、レイアウト（アイコン有無・padding）もページごとに異なる
- [ ] **優先度7: ローディングの統一** — Skeleton / loader アイコン+「取得中…」/ テキスト「読み込み中…」の3様式が混在。三点リーダも「…」と「...」の混在を解消
- [ ] **優先度8: タスク・チャンネルの削除機能** — 削除機能自体が未実装。仕様として削除を設けるか、設けるなら統一した削除 UI に乗せるかを方針決定する
