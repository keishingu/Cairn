# プロダクト戦略メモ — 展開戦略と魅力向上の優先課題

作成日: 2026-06-11

LP（`apps/web/public/lp/index.html`）・`docs/` 一式・コードベースの実装調査をもとに、
「世の中への展開に必要なこと」と「魅力的なプロダクトに仕上げるために必要なこと」を整理した議論の記録。

---

## 1. 前提: 現状認識

### 実装の広さは十分

プロジェクト管理・チャット・カレンダー・カンバン・タスク・ファイル・ギャラリー・
AIアシスタント（RAG/pgvector）・通知（アプリ内/Push）・検索・オンボーディングまで一通り動く。

### 一方で「差別化の柱」がことごとく未実装または浅い

| 差別化の柱（docs/01 で宣言） | 実装状況 |
|---|---|
| チャット中心 | 5秒ポーリング。スレッドは DB スキーマ（`parentMessageId`）のみで UI 未実装 |
| AGENTS.md による AI カスタマイズ | DB スキーマに `agentsMd` フィールドがあるだけ。UI・実行系とも未実装 |
| HTML テンプレート出力 → チャットにレンダリング | スキーマのみ。未実装 |
| Slack / Teams / カレンダー連携 | Google Calendar 連携を除き Phase 2 以降のまま |
| ギャラリー | アップロード・閲覧のみ。コメント・いいね・アルバム・共有は未実装（EXIF の GPS 座標は抽出・保存済み） |

このため現状は「丁寧に作られた汎用 PM ツール」止まりであり、
**「これがあるから Cairn を選ぶ」という尖りを 3〜4 本、深く仕上げること**が最大のテーマ。

### LP の宣言と実装のギャップ（信頼リスク）

- LP は「Self-Hosted / `docker compose up` で起動」を謳うが、実際は Vercel + Supabase + Inngest + OpenAI のマネージド依存構成
- LP は「Bring Your Own AI」を謳うが、技術判断は「OpenAI のみ」
- LP の CTA「Try Demo」に対応する、登録不要のデモ環境がない
- LP がリンクする Documentation / FAQ / Changelog に対応する公開ドキュメントがない

このギャップを放置したまま集客すると、OSS コミュニティ形成の初動で信頼を失う。

## 2. 魅力的なプロダクトに仕上げるための優先課題

### 最優先の 3 つ

1. **チャットのリアルタイム化**
   - 5秒ポーリング → Supabase Realtime へ移行。スレッド UI・タイピングインジケータ・楽観的更新まで含め「Slack と同等の手触り」に
   - 「チャット中心」を名乗るプロダクトでメッセージが5秒遅れて届くのは、最初の10分で離脱される種類の欠陥
2. **AGENTS.md カスタム AI + HTML テンプレート出力の実装**
   - 唯一無二の差別化が未実装のまま。現状の AI は「RAG 付き汎用チャットボット」で Notion AI / ChatGPT との違いを説明できない
   - 「チャット履歴とファイルを読んで山行計画書の HTML を生成し、そのままチャットに貼られる」デモが動いた瞬間に初めて唯一無二になる
3. **サンプルデータ入りオンボーディング**
   - 現状はワークスペース作成 → 招待 → 完全な空状態。サインアップ直後にデモプロジェクト（チャット・ファイル・タスク・写真入り）を自動生成し、最初の5分で動く姿を見せる

### 続く優先課題

4. **AI を「別タブ」からワークフローの中へ** — チャンネル要約、会話からのタスク抽出・起票、ステータス変更の提案。AI が読むだけでなく「書ける」ようにする
5. **会話と構造をつなぐメカニクス** — メッセージの1クリックタスク化、決定事項のピン留め → 概要タブ集約、ステータス変更・ファイル追加のチャットへのシステムメッセージ通知
6. **ギャラリーを感情の資産へ** — コメント・いいね・アルバム・共有。EXIF の GPS 座標を既に保存しているため、地図上に山行写真をプロットする画面は費用対効果の高い独自機能になる
7. **操作の速さと気持ちよさ（Linear 水準のクラフト）** — ⌘K コマンドパレット（LP モックに存在、未実装）、キーボードショートカット、体感速度
8. **モバイル体験** — ターゲット（学生・現場職）は PC の前にいない。Expo WebView ラッパーから、Push 通知・チャット・写真アップロードがネイティブ品質で動く水準へ
9. **テストと品質保証の土台** — 現状テスト20ファイル・E2E なし。主要フロー（サインアップ → プロジェクト作成 → チャット → AI）の E2E を1本通すだけでも改善速度が変わる
10. **戦略: 広げるより山岳部で「愛される」まで掘る** — 山行計画書テンプレート・装備リスト・入山届・気象連携など特化の深掘りで「この用途なら Cairn 以外ありえない」状態を数大学で作る。横展開は AGENTS.md とテンプレート差し替えで実現する設計に既になっている

## 3. 世の中への展開（GTM）に必要なこと

プロダクトの磨き込みと並行して、展開時には以下が必要になる。

1. **`docker compose up` で本当に動くセルフホスト構成**（+ Helm chart）— LP の約束を守る最優先項目
2. **AI のプロバイダ非依存化** — Vercel AI SDK の抽象化を活かし Anthropic / Gemini / ローカル LLM（Ollama）対応。セルフホスト層の導入可否を分ける
3. **サインアップ不要の即時デモ環境** — シードデータ入り・自動リセット
4. **公開ドキュメントサイト（日英）** — インストールガイド・管理者ガイド・AGENTS.md の書き方・API リファレンス。アプリ本体の i18n も世界展開の前提
5. **Slack 通知 + ICS / Google Calendar 一方向同期の前倒し出荷** — 差別化の根拠を実装で示す
6. **データインポート** — CSV / Slack エクスポート / Notion / Backlog からの乗り換え導線
7. **業種別テンプレート集** — ステータス定義・ワークフロー・AGENTS.md プロンプト・HTML テンプレートのワンクリック適用。FDE 導入支援のノウハウをプロダクト資産化し、スケールさせる
8. **OSS コミュニティ立ち上げ** — 英語 README・CONTRIBUTING・公開ロードマップ・good first issue。山岳部ビーチヘッドで実運用事例を作り、ケーススタディとして展開
9. **オープンコア型の収益設計** — Cairn Cloud（ホスティング版）+ Enterprise 機能（SSO/SAML・監査ログ・細粒度 RBAC・バックアップ）
10. **時間軸の整理** — 短期: 1・3・4（LP の約束を守る = 信頼）/ 中期: 5・6 とプロダクト磨き込み / 長期: 7〜9（スケールと収益化）

- AI: gpt-4o / gpt-4o-mini + text-embedding-3-small（pgvector 1536次元）。RAG・ソースチップ表示・Tavily Web 検索は実装済み
- チャット: メンション・未読既読（`channelReadStates`）・リアクション・添付・編集削除は実装済み。スレッド UI とリアルタイムが未実装
- 検索: 字句検索（チャンネル内・横断）は実装済み。⌘K コマンドパレットは未実装
- 通知: アプリ内・Web Push・Expo 対応済み（30秒ポーリング）
- core ユースケース: CreateProject / UpdateProjectStatus / PostMessage / UploadGalleryItem / GenerateAiReply。テストは `create-project.test.ts` の1本のみ
- TODO/FIXME コメントはほぼなし（スキーマ先行・UI 未追従という形で未実装が存在する）
