# AIメンバー設計書

作成日: 2026-06-11
ステータス: 構想・議論段階（実装未着手）

AIを独立した「AIアシスタントタブ」から、**ワークスペースに参加する一人のメンバー（人格を持ったエージェント）**へ進化させるための設計方針。
[`docs/09_product_strategy_notes.md`](./09_product_strategy_notes.md) の優先課題 2（AGENTS.md カスタムAI）・4（AIをワークフローの中へ）・5（会話と構造の接続）を、この1つの機能で同時に回収することを狙う。

---

## 1. コンセプト

### AIは「機能」ではなく「メンバー」

- AIエージェントはワークスペースの正式なメンバーとして `channel_members` に参加する
- 発言は通常の `messages` 行として記録され、メンション・未読・通知・リアクション・監査の既存メカニズムにそのまま乗る
- 人格・役割・行動規範は組織ごとに AGENTS.md（Markdown）で定義する。例:「あなたはこの山岳部の主務です。山行3日前までに計画書が出ていなければ催促してください」

### 参考にした構想と、意図的に変える点

OpenClaw 等の「半自動で動く人格型パーソナルアシスタント」を参考にするが、
**個人アシスタント（1対1）とチームの共有空間（多対多）の違い**から、以下は意図的に変える。

| 観点 | OpenClaw 型 | Cairn の方針 |
|---|---|---|
| 自律性 | 常時自走 | 段階的に解放（後述の Stage 1→4）。発言頻度に上限を設ける |
| 行動の権限 | 本人が全責任を負うため自由 | 破壊的・不可逆な操作は提案→人間の承認制 |
| 記憶の帰属 | 主人（個人）について記憶 | プロジェクト・ワークスペースについて記憶（何が決まったか） |
| 人格の濃度 | 固定的 | AGENTS.md でカスタマイズ対象とする（山岳部=マスコット的 / 法人=実務的） |

## 2. なぜこの設計が Cairn に合うか

1. **「チャンネル = エンティティ」設計と噛み合う**（[`docs/07`](./07_notifications_and_unread.md)）。
   AIをチャンネルメンバーにすれば、メンション検知・通知・未読の仕組みを再利用でき、「AIタブ」を別途作り込むより実装が薄い。
2. **DBスキーマが既に先取りしている**。
   - `ai_agents`: `scope`（workspace/project）・`name`・`model`・`systemPrompt`・`agentsMd`・`htmlTemplate`・`isActive` を保持済み（`packages/db/src/schema/ai.ts`）
   - `messages.messageType`: `'text' | 'html' | 'system'` が定義済み（`packages/db/src/schema/enums.ts`）。HTML出力のチャットレンダリングと、AI行動のシステムメッセージ通知が想定済み
3. **FDE的導入支援との接続**。導入支援の納品物が「その組織専用のデジタル主務の AGENTS.md」になり、差別化ストーリーが一本につながる。
4. **初期ターゲットとの相性**。大学の部活では「便利な機能」より「もう一人の部員」のほうが感情的に受け入れられやすく、口コミの起点になる。

## 3. データモデル

### 既存資産（変更不要）

- `ai_agents` — 人格定義（AGENTS.md・HTMLテンプレート・モデル・スコープ）
- `channels` / `channel_members` / `messages` / `channel_read_states` — 参加・発言・未読の基盤
- pgvector ドキュメントチャンク — RAGコンテキスト

### 追加・変更が必要なもの

| 項目 | 内容 |
|---|---|
| AIのアイデンティティ | `messages.senderId` は `profiles.id` NOT NULL のため、エージェントごとに profile 行を作る（認証ユーザーなし）。`profiles` に `kind: 'human' \| 'agent'` 相当の識別カラム、または `agent_id` 参照を追加 |
| 承認待ちアクション | `ai_pending_actions` テーブル（agent_id / channel_id / action_type / payload / status / approved_by）。チャット内インラインカードの裏側 |
| エージェント記憶 | Stage 4 で `ai_agent_memories`（workspace/project スコープ + pgvector）。それまでは既存チャンクで代替 |
| 監査 | AIの全行動を `messageType: 'system'` のメッセージとしてチャンネルに記録（専用テーブルは当面不要） |

## 4. 自律性の4段階ロードマップ

権限は一度に与えず、**各段階で信頼を獲得してから次を解放する**。

### Stage 1 — 呼べば来るメンバー（受動）

- ワークスペース作成時にデフォルトエージェント（profile 行 + `ai_agents` 行）を自動作成し、全プロジェクトチャンネルに参加させる
- `@エージェント名` メンションで起動し、そのチャンネル＝プロジェクトのRAGコンテキスト（ファイル・チャット履歴・メンバー・ステータス）で返答
- AGENTS.md（workspace スコープ + project スコープの上書き）を system prompt に合成
- `htmlTemplate` による山行計画書等のHTML生成 → `messageType: 'html'` でチャットにレンダリング
- 既存 `/ai` タブはエージェント設定画面（AGENTS.md 編集・テンプレート管理）へ役割を移す

**完了条件**: チャンネル内で `@主務 計画書つくって` → HTML計画書がチャットに貼られるデモが動く。

### Stage 2 — 手を持つ（提案 → 承認）

- ツール呼び出しで `packages/core` のユースケース（タスク作成・ステータス変更・決定事項ピン留め）を実行可能にする
- ただし直接実行せず、チャット内に承認カードを出す:「タスク3件を起票しますか？ [承認] [編集] [却下]」
- 承認カードは `ai_pending_actions` + 専用メッセージ表現で実装。承認した人間が実行者として記録される
- 実行結果は `messageType: 'system'` でチャンネルに必ず可視化する

**完了条件**: 会話の流れから「決まったこと」をタスク化する一連の操作が、チャットを離れずに完結する。

### Stage 3 — 心拍を持つ（半自動）

- Inngest cron で各プロジェクトを定期巡回（ハートビート）し、以下を検知したときだけ発言する
  - 山行日（`Project.start_date`）が近いのに計画書ファイルがない
  - ステータスが長期間動いていない（例: 審査中のまま7日）
  - 結論が出ないまま流れた議論・未回答のメンション
- **発言の規律**（製品の生死を分けるため必須）:
  - 発言頻度上限: 1プロジェクトにつき1日1回まで（設定変更可）
  - 静寂時間帯の尊重
  - 確信度が低い場合は発言しない（沈黙をデフォルトとする）
- コスト制御: 巡回の一次判定は gpt-4o-mini、発言が必要と判断したときのみ gpt-4o に昇格

**完了条件**: 1週間運用して「催促が役に立った」体験と「うるさくてミュートした」苦情の比率が前者に倒れる。

### Stage 4 — 記憶と人格の深化

- プロジェクト横断の長期記憶（`ai_agent_memories` + pgvector）:「この部は毎年6月に新歓山行をやる」「去年の剱岳は装備リスト確定が遅れた」
- 記憶を踏まえた先回り:「去年は装備リストが遅れたので、今年は早めに声をかけますね」
- AGENTS.md の人格定義と記憶の組み合わせが、模倣困難な価値になる

## 5. 設計原則

1. **沈黙がデフォルト** — 共有チャンネルでは発言の希少性が信頼の源泉。迷ったら黙る
2. **不可逆な操作は承認制** — ステータス変更・削除・外部送信は必ず人間の承認を経る
3. **すべての行動を可視化** — AIの操作は必ずチャンネルにシステムメッセージとして残す。「いつの間にか変わっていた」を一度も起こさない
4. **人格の濃度は設定可能** — マスコット的人格を強制しない。AGENTS.md で組織が決める
5. **記憶はプロジェクトに帰属** — 個人の嗜好ではなく、チームの決定と経緯を記憶する

---

## 6. リスクと対策

| リスク | 対策 |
|---|---|
| 発言過多によるミュート・形骸化 | 頻度上限・静寂時間・確信度しきい値（Stage 3 の規律） |
| ハルシネーションによる誤った状態変更 | 承認制（Stage 2）+ 全行動の可視化 |
| LLMコストの増大（巡回 × ワークスペース数） | gpt-4o-mini による一次判定・発言時のみ gpt-4o |
| 横展開先での人格の不適合 | AGENTS.md による人格カスタマイズを前提に設計 |
| 擬人化による過信 | AI発言には明示的なエージェントバッジを常時表示 |
